# Astextract Tool Summary

## Purpose

The `astextract` tool serves to convert Go source code into its abstract syntax tree (AST) representation. Significantly, the output generated by `astextract` is 100% valid Go code. This allows developers to directly utilize the generated AST within their Go projects.

## Primary Use Case

The primary application of `astextract` is to facilitate the creation of typesafe `go generate` tools. By providing a concrete Go representation of the AST, developers can build tools that operate on this structure with the benefits of Go's type system, enhancing reliability and maintainability.

## Key Features

- **Valid Go Code Output:** The AST representation produced by `astextract` is entirely valid Go code. This means it can be compiled and used directly within other Go programs or `go generate` tools without any intermediate processing steps.
- **Compact AST Representation:** To ensure the output is concise, `astextract` omits struct fields in the AST representation that have zero or null values. This reduces clutter and focuses on the essential structural information of the code.
- **Position-Independent AST:** The tool strips absolute position information (like line and column numbers) from the AST. This makes the generated ASTs more stable and less prone to changes when only whitespace or formatting modifications occur in the source code. It focuses the AST on the structural and semantic aspects of the code rather than its textual layout.

## Code Structure and Key Components

The `astextract` tool is organized into several key Go files, each with a distinct role:

- **`astextract.go`**: This file contains the core logic of the tool. It is responsible for:
    - Parsing command-line arguments using the standard `flag` package. This includes arguments for specifying the input Go file and potentially other options.
    - Reading the content of the input Go source file.
    - Housing the main `Parse` function. This function orchestrates the entire AST conversion process. It utilizes the `go/parser` package from the Go standard library to parse the input Go source code into an AST.
    - Defining `Main1`, which serves as the primary operational entry point for the tool's logic, likely called after initial setup.

- **`cmd/astextract/main.go`**: This file acts as the main entry point for the executable. Its primary responsibility is to be a minimal wrapper that calls `astextract.Main1()` from the `github.com/goki/pi/astextract` package. This effectively launches the tool and initiates the AST extraction process.

- **`print.go`**: This file implements the custom logic for printing the AST into a Go syntax-compatible representation. It is a crucial component for achieving the tool's goal of producing usable Go code.
    - It is an adaptation of the standard library's `go/ast/print.go`.
    - It is modified specifically to output Go syntax that represents the AST structure, rather than just a debug printout.
    - A key feature is its use of `FieldFilter` and specific filter implementations like `ZeroFilter`, `PosFilter`, and `KeywordFilter`. These filters are functions that determine whether a particular field of an AST node should be included in the output. This allows for:
        - `ZeroFilter`: Omitting fields that have zero or nil values, leading to a more compact output.
        - `PosFilter`: Stripping absolute position information (line and column numbers) from the AST nodes.
        - `KeywordFilter`: Likely involved in ensuring that Go keywords are correctly represented in the output AST.
    - This filtering mechanism is essential for controlling the verbosity and content of the printed AST, ensuring it is both clean and valid Go code.

- **`tokens.go`**: This file provides a mapping from `go/token` constants (e.g., `token.IDENT`, `token.STRING`, `token.ADD`) to their string representations (e.g., `"IDENT"`, `"STRING"`, `"ADD"`). This mapping is primarily utilized by `print.go` to generate readable and accurate AST output, ensuring that token types are correctly represented as strings in the generated Go code.

## Additional Features and Aspects

### Web Application

`astextract` is also available as a web application, which can be accessed at: https://astextract.lu4p.xyz/

The web application is built using the `go-app` package.

### Installation

To install the `astextract` command-line tool, use the following command:

```bash
GO111MODULE=on go get -u github.com/lu4p/astextract/cmd/astextract
```

### Usage Examples

The basic usage of `astextract` is to provide it with a Go file:

```bash
astextract [flags] file
```

For more detailed and up-to-date usage information, you can use the `-h` flag:

```bash
astextract -h
```

**Example:**

Given a `main.go` file with the following content:

```go
package main

func main() {
	println("Hello, World!")
}
```

Running the command `astextract main.go` will produce the following AST representation:

```go
&ast.File {
  Package: 1,
  Name: &ast.Ident {
    Name: "main",
  },
  Decls: []ast.Decl {
    &ast.FuncDecl {
      Name: &ast.Ident {
        Name: "main",
      },
      Type: &ast.FuncType {
        Params: &ast.FieldList {},
      },
      Body: &ast.BlockStmt {
        List: []ast.Stmt {
          &ast.ExprStmt {
            X: &ast.CallExpr {
              Fun: &ast.Ident {
                Name: "println",
              },
              Args: []ast.Expr {
                &ast.BasicLit {
                  Kind: token.STRING,
                  Value: "\"Hello, World!\"",
                },
              },
            },
          },
        },
      },
    },
  },
}
```

The README also mentions an option to output the AST to a file and includes an example of how to convert the `go/ast` back to Go code using `printer.Fprint`. The command `astextract -out=filename main.go` generates a Go file containing the AST of `main.go` and an example on how to generate Go code from the AST.
